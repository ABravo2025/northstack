Northstack Current Process Flow

Live at app.joinnorthstack.com. This page shows the current architecture, onboarding, settings, Time Off, and Clients-redesign (Company/Contact/Pipeline/Opportunity) flows for Northstack. Last synced 2026-07-27 — see docs/current-process-flow.md for the full technical detail behind each diagram, and docs/database-schema.md for the data model.

Where it lives

Frontend + Backend One Vercel project. Static React/Vite build plus an Express app running as a serverless function (api/index.ts).
Database Neon (serverless Postgres) via Prisma, same connection in local dev and production.
Domain + SSL app.joinnorthstack.com (Cloudflare-registered domain), SSL issued automatically by Vercel.
Deploys Two branches, two pipelines: push to main deploys the app, push to landing deploys the marketing site — each via its own GitHub Actions job (vercel deploy --prod).
Email Real transactional email (invitations) via Zoho Mail SMTP from no.reply@joinnorthstack.com — no third-party ESP.
Resilience Async route errors are caught and returned cleanly instead of crashing the process; Prisma retries transient connection failures.

Settings — one hub, module settings live inline

One hub Both the sidebar gear icon and the TopBar user menu land on /settings — the two-hub split shown in earlier versions of this page was merged 2026-07-16.
Mi cuenta / Empresa Profile (every role) vs. Appearance/Users/Public Forms/Pipelines (owner/admin only) — two groups inside the same hub.
Custom Fields & Statuses moved out Not in Settings at all anymore — a "..." menu on each custom-field column header, and a single "Manage options" popover on the Status column, live directly in whichever table they belong to.
Ownership is unique Promoting someone to owner is an atomic transfer (the acting owner is demoted to admin in the same transaction) — a tenant can never have zero or multiple owners.

HR & Clients modules

Parity Employees and Clients share the same pattern: dynamic custom fields, client-side search, inline edit.
Generic custom fields One CustomFieldValue model (tenantId + entityType + entityId) — no schema change needed when a future module (e.g. Payments) is added.
Employee self-access An Employee can optionally link to a User via invite, giving them their own login.
Statuses are configurable now No more fixed enums — StatusDefinition is a per-tenant, per-module catalog (name, color, order, default, active). Every status change is logged in StatusHistoryEntry as a name snapshot, not a live FK.
Employee hierarchy Employee.managerId ("reports to"), self-referential, with cycle detection. Every tenant owner gets an auto-created Employee record so they always appear as a manager option.

Time Off system — complete, 7/7 pieces

Configurable policies TimeOffPolicyDefinition per tenant — name, color, accrual (fixed annual or monthly), days/year, paid, requires approval.
Per-employee assignment Policies aren't tenant-wide by default — assigned per employee via EmployeeTimeOffPolicy.
Hierarchy-routed approval A request's approver snapshots the employee's manager at request time; owner/admin can always override. No-approval-needed policies auto-approve instantly.
Balance, derived No balance table — computed on the fly from assignment date, accrual settings, and approved/pending requests for the current calendar year.
Calendar on Overview /overview is now the home screen after login, showing a month calendar of who's on approved or pending time off — open to every tenant member, not just admins.
flowchart TD A[Employee requests time off from an assigned policy] --> B{Policy requires approval?} B -->|No| C[Auto-approved instantly] B -->|Yes| D[Pending, routed to their manager] D --> E[Manager approves/rejects] D --> F[Owner/Admin can override] E --> G[Shows on the tenant-wide calendar] C --> G

Clients redesign — Company / Contact / Pipeline / Opportunity

3 sidebar modules Companies, Contacts, Opportunities — replacing the flat Client model, which stays fully live in parallel until a separate future cutover.
Won → Customer, automatic An Opportunity reaching a stage with outcome: won auto-advances its Company to the Customer status. Churned has no automatic trigger yet (depends on a Contract entity that doesn't exist).
Form-driven Company matching A Contact-type Public Form submission matches or creates a Company by the submitter's email domain, then optionally auto-creates an Opportunity in a configured Pipeline's first stage.
Data migration: staging only so far An idempotent backfill script moved 21 legacy Clients into Companies/Contacts on staging. Not yet run against production — waiting on the user's review.
flowchart TD A[Contact Form submitted] --> B{Email domain matches an existing Company?} B -->|Yes| C[Reuse that Company] B -->|No, generic domain| D[Contact only, no Company] B -->|No, specific domain| E[New Company created - Prospect] C --> F{Pipeline configured on the form?} E --> F F -->|Yes| G[Opportunity auto-created, first stage] F -->|No| H[Just the Contact] G --> I[Opportunity reaches a won stage] I --> J[Company status auto-advances to Customer]
